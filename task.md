# DXUI v2 — Technical Brief & Mission

> **Статус:** единственный источник требований. Спецификация (design rationale): `dxui-v2-plan/index.html`.
> **Что это:** полный редизайн `mta-dx-ui` — клиентского Lua UI-фреймворка для MTA:SA. Репозиторий — greenfield.
> **Роль исполнителя:** senior Lua engineer. Принимаются решения в пределах обозначенных полномочий; фиксируются решения, помеченные как LOCKED.

---

## 1. Миссия

Retained-mode UI-фреймворк для MTA:SA: декларативные виджеты над собственным конвейером кадра (свойства → инвалидация → замер → раскладка → холст → dxDraw). Замена CEGUI и конкурента DGS по трём осям: предсказуемая производительность (budget-дрифт невозможен по построению), API без строковых протекций, нативная расширяемость (новый виджет = 1 файл, 0 правок ядра).

**Метрики успеха:** 1000 статичных виджетов ≤ 2 мс/кадр; список 10 000 строк (виртуализованный) ≤ 2 мс/кадр; миграция DGS-сценария ≤ 1 дня по таблице соответствия; time-to-first-UI ≤ 5 минут.

## 2. Платформенная реальность (проверено, не обсуждается)

| # | Факт | Следствие |
|---|---|---|
| P1 | MTA:SA = Lua 5.1 (интерпретатор, не JIT) | нет `goto`, 5.2+-синтаксиса; оптимизации — структура данных и кэш, не микро-магия |
| P2 | Экспорты межресурсные имеют overhead; WIKI запрещает их в горячем пути | фасад для потребителей: `loadstring(exports.dxui:import(2))()` — экспорт возвращает Lua-код-строку один раз; в кадре ноль exports |
| P3 | Функции в таблицах не сериализуются через границу экспортов | единственный корректный формат фасада — код-строка (не таблица) |
| P4 | Кадр растеризуется целиком | damage-tracking неинвариантен; рычаг — RT-кэш статичных поддерёв + минимизация Lua-работы в кадре |
| P5 | Нет composition-событий IME для DX-текста | CJK-ввод в DX не обещаем; поле ввода строится на `onClientCharacter` |
| P6 | `dxDrawImage` поворачивается, `dxSetTransform` существует, `dxDrawImageSection` есть | transforms, 9-slice, клиппинг — реализуемы платформой |
| P7 | `dxSetRenderTarget` — глобальное состояние | строго через defer-обёртку с восстановлением прежней цели |

**Whitelist MTA-API:** платформенные вызовы разрешены только в `render/backend_mta.lua`, `input/dispatcher.lua`, `boot.lua`. Линт в CI (проверь невозможность ложных срабатываний по строкам/комментам — паттерн на вызов, не на упоминание).

## 3. Архитектура (LOCKED)

```
source/
  boot.lua        # точка сборки + единственный платформенный мост ввода/кадра
  core/           # class, signal, pool, time, log — zero-dependency
  dom/            # node, prop (схема+инвалидация), tree_ops (Z-порядок)
  layout/         # measure, flex, grid, anchors, constraints
  widget/         # base, registry, composition (slots), binding
  widgets/        # 1 файл = 1 виджет, только здесь спецификации
  render/         # canvas (command buffer), backend_mta, backend_headless
  style/          # tokens, theme, states, transitions
  input/           # dispatcher, hit_test (spatial hash), focus, gesture
  anim/           # tween, easing (единый клок из core/time)
  text/           # headless-ядро текстового ввода: caret/selection/undo/blink
  api/            # exports.lua (import-фасад), resource isolation
  debug/          # inspector, profiler, stats overlay
```

**Правило зависимостей:** только вниз по списку. `core/` ни от кого. Нарушение — ошибка сборки.

### Ключевые контракты

**Свойства** — сердце системы. Схема: `{ type, default, required, invalidates, doc, onSet }`. Запись — только через генерируемые метаметоды. Инвалидация — dirty-списки (LAYOUT/RENDER), дедуп узла в списке, обход пассами списка, не дерева (по образцу Flutter PipelineOwner). Равное значение не инвалидирует. Необъявленное свойство — ошибка в dev.

**Сигналы** — по контракту GoodSignal: connection-объекты, отложенная отписка во время эмита, `once`, слабые ссылки на подписчиков (уничтоженный виджет отсоединяется сам), изоляция ошибок подписчика в dev (pcall+traceback), prod — без обёрток. Внутри фреймворка `triggerEvent` запрещён — мост к платформенным событиям один, в `boot.lua`.

**Ввод** — очередь → раздача один раз за кадр до пасса раскладки; hit-test против геометрии прошлого кадра (то, что видел игрок). Пространственный хеш, перестройка лениво при структурном изменении. Фокус: Tab ≠ стрелки в текстовых полях, модальные ловушки с точкой возврата.

**Виджет:** `Widget "Button" { props, theme, slots, render, handlers }`. Экземпляр: `ui.Button { props = {...} }` — конструктор, не мутирующая фабрика. Все props задокументированы (без `doc` валидатор красный) — документация генерируется из схемы.

**Раскладка** — двойные координаты `{ scale, offset }` (UDim2-семантика), авторазмер вглубь, конфликт absolute-vs-layout → layout побеждает (dev-warning). Кэш дерева раскладки инвалидационный.

**Оптимизации, заложенные в дизайн** (реализуй все): dirty-списки; RT-кэш статичного поддерева с инвалидацией по ключу токенов; виртуализация списков (узлов O(видимых)+2); пулы (zero allocations steady-state); заморозка скрытых поддеревьев (skip из пассов); time-slicing тяжёлой работы ≤ 0.5 мс/кадр квантом; коалесцирование записей; auto-LOD эффектов при серии просадок.

## 4. Этапы (каждый — самодостаточная поставка)

| # | Этап | Exit criteria (измеряется) |
|---|---|---|
| G0 | core/ | unit-тесты зелёные на headless; signal проходит стресс: disconnect-in-emit, weak-collection, error isolation |
| G1 | dom/: prop + node + tree_ops | 100-узловое дерево создаётся/уничтожается: живых узлов 0, подписок 0 (счётчики) |
| G2 | render/: canvas + backend_mta + boot | headless-бенчмарк: 1000 rect ≤ 2 мс (медиана 120 кадров после прогрева); демо-прямоугольник виден в игре |
| G3 | layout/ | golden-тесты координат; порт сценария v1 (окно + scrollpanel) — бит-в-бит |
| G4 | widget/ + 6 виджетов (Panel, Label, Button, Edit, List, Window) | демо-экран кликается, drag окна, ввод текста; validate требует doc — зелёный |
| G5 | input/ полный + focus | Tab/стрелки/модалы/drag — автотесты + ручная матрица в игре |
| G6 | style/ + anim/ | смена темы 300 виджетов ≤ 5 мс; hot-reload темы в живом режиме |
| G7 | api/, debug/, dxui.py (build/validate/test/wiki/new-widget), демо-ресурс 5 сценариев | внешний потребитель-ресурс собирает UI через `import(2)` без внутренних файлов; бюджеты из раздела 1 — зелёные в CI |

**Формат поставки этапа:** зелёные тесты → changelog → тег. Этап без exit criteria не закрывается, независимо от объёма написанного.

## 5. Инструменты и качество

- **Тесты:** headless (backend_headless) — без MTA; платформенные вещи — помечены и проверены вручную по чек-листу с приложенным видео/скринами. Раннер — свой, Lua 5.1-совместимый, запуск из `dxui.py test`.
- **Бюджеты в CI:** тест деградации падает при превышении. Методика замеров фиксирована: медиана 120 кадров, прогрев.
- **Профилировщик встроенный** — с причинностью dirty (кто вызвал), per-widget стоимость, `dxui:stats` overlay.
- **Прозрачность зависимостей:** граф модулей генерируется из require-цепочки; циклы — ошибка сборки.

## 6. Полномочия и красные линии

**Решаешь ты (не согласуя):** внутренняя структура файлов внутри слоя; выбор алгоритмов в пределах бюджетов; форматы бенчмарков; тестовый дизайн; любые рефакторинги, сохраняющие контракты этапа.

**Red lines (нарушение = возврат):**
1. MTA-вызовы вне whitelist (раздел 2).
2. `triggerEvent` внутри фреймворка.
3. Аллокации в установившемся кадре (zero-alloc steady-state).
4. Строковые ключи/конкаты в горячем пути кадра.
5. Breaking-change фасада `import(2)` после G7.
6. Новые внешние зависимости (библиотека самодостаточна).
7. Расширение скоупа этапа без фиксации exit criteria.

**Опасные зоны — известные ловушки, учесть в коде:** nil-дыры в children массивах (только insert/remove-парность); глобальное состояние `dxSetRenderTarget`; колесо мыши без keyup; `collectgarbage("count")` для памяти Lua; события приходят после рендера текущего кадра — не полагаться на порядок внутри кадра без явной синхронизации пассов.

## 7. Определение готовности (Definition of Done)

Проект завершён, когда:
1. Все G0–G7 закрыты по exit criteria, теги проставлены.
2. `grep dxDraw source/` → только `backend_mta.lua`; `grep "exports\." source/` → только объявления в `api/`.
3. Внешний ресурс собирает интерфейс через `import(2)`: логин, список с поиском, HUD, модальные диалоги, смена тем.
4. CI: validate + test + бюджеты зелёные; WIKI генерируется.
5. Двухнедельный срок эксплуатации демо-ресурса — ни одной утечки (профайлер: живых объектов после cleanup = 0).
