# DXUI v2 — Technical Brief & Mission

> **Статус:** единственный источник требований. Этот документ самодостаточен: никаких внешних файлов, репозиториев и спецификаций для исполнения не требуется.
> **Что это:** greenfield-проект — UI-фреймворк «с нуля» (v2). Он приходит на смену существующему проекту v1, но у вас его НЕТ и он не нужен: ниже зафиксированы только уроки v1, всё остальное — новые решения.
> **Роль исполнителя:** senior Lua engineer. Принимаются решения в пределах обозначенных полномочий; фиксируются решения, помеченные как LOCKED.

---

## 0. Контекст (обязательно к прочтению — что вы строите и зачем)

**Платформа.** Multi Theft Auto: San Andreas (MTA:SA) — многопользовательская модификация GTA:San Andreas. Сервер = набор Lua-скриптов («ресурсов»); клиент скачивает и исполняет клиентскую часть ресурсов. Клиентский Lua — 5.1, те же данные, один общий экран.

**Что такое «DX»** — это низкоуровневый immediate-mode API рисования (`dxDrawRectangle`, `dxDrawText`, `dxDrawImage`). Он ничего не помнит: всё, что не перерисовано в текущем кадре, исчезает. Кадр рисуется в обработчике `onClientRender` — 60+ раз в секунду. Родной CEGUI (`guiCreate*`) устарел и ограничен.

**Боль.** Строить на голом `dxDraw*` интерфейс сложнее трёх кнопок — больно: нет дерева, событий, раскладки, тем. Существуют сторонние библиотеки (DGS, dxLibrary), но: у DGS — строковые свойства, полный обход дерева каждый кадр, утечки видеопамяти; у dxLibrary — процедурные глобалы и позиционные boolean-аргументы.

**Продукт.** DXUI v2 — один MTA-ресурс, который другие ресурсы подключают и строят интерфейсы декларативно: окно → кнопки → списки, с деревом узлов, раскладкой, темами, вводом и оптимизациями. Потребители — авторы игровых серверов MTA (сотни активных серверов, тысячи разработчиков).

**Уроки v1 (почему переписываем, фиксируем без деталей):** ручной порядок подключения в meta.xml (ошибки порядка загрузки); строковый поиск стилей в горячем пути; pcall на каждый тик вместо измеряемой изоляции ошибок; отсутствие схемы свойств — API непредсказуем; ноль тестов. Каждое из этих решений в v2 закрыто архитектурно (раздел 3).

**Как выглядит результат** для конечного автора сервера:

```lua
local ui = loadstring(exports.dxui:import(2))()   -- импорт API один раз

ui.Window {
  title  = "Инвентарь",
  layout = { dir = "column", gap = 8 },
  children = {
    ui.Edit   { placeholder = "Поиск...", onText = loadItems },
    ui.GridList { id = "items", virtualized = true },
    ui.Button  { text = "Закрыть", onPress = function() end },
  },
}
```

## 1. Миссия

Retained-mode UI-фреймворк для MTA:SA: декларативные виджеты над собственным конвейером кадра
(свойства → инвалидация → замер → раскладка → холст → dxDraw). Замена CEGUI и конкурента DGS по трём осям:
предсказуемая производительность (budget-дрифт невозможен по построению), API без строковых протекций,
нативная расширяемость (новый виджет = 1 файл, 0 правок ядра).

**Целевые метрики:**

| Характеристика | Требование | Способ контроля |
|---|---|---|
| Производительность кадра | 1000 виджетов ≤ 2 мс/кадр | автоматический бенчмарк в CI, падение сборки |
| Виртуализированный список | 10 000 строк ≤ 2 мс/кадр | тот же |
| Расширяемость | новый виджет = 1 файл, 0 правок ядра | контрактный тест |
| Тестируемость | ≥ 70 % ядра покрыто без среды MTA | собственный раннер + headless-бэкенд |
| Стабильность фасада | 0 нарушающих изменений `import(2)` после G7 | контрактные тесты |
| Изоляция платформы | 0 вызовов MTA-API вне whitelist | статический линт в CI |
| Скорость итерации | hot-reload тем и виджетов | инспектор из стандартной поставки |
| Time-to-first-UI | ≤ 5 минут от установки до окна | scripted-сценарий проверки |

**Область применения:** интерфейсы игровых ресурсов: меню, инвентарь, диалоги, HUD.
**Не входит:** серверная логика интерфейса (фреймворк строго клиентский); поддержка устаревшего CEGUI.

## 2. Платформенная реальность (проверено, не обсуждается)

| # | Факт | Следствие |
|---|---|---|
| P1 | MTA:SA = Lua 5.1 (интерпретатор, не JIT) | нет `goto`, 5.2+-синтаксиса; оптимизации — структура данных и кэш, не микро-магия |
| P2 | Экспорты межресурсные имеют overhead; WIKI запрещает их в горячем пути | фасад для потребителей: `loadstring(exports.dxui:import(2))()` — экспорт возвращает Lua-код-строку один раз; в кадре ноль exports |
| P3 | Функции в таблицах не сериализуются через границу экспортов | единственный корректный формат фасада — код-строка, не таблица |
| P4 | Кадр растеризуется целиком | damage-tracking в классическом виде неинвариантен; рычаг — RT-кэш статичных поддерёв + минимизация Lua-работы в кадре |
| P5 | Нет composition-событий IME для DX-текста | CJK-ввод в DX не обещаем; текстовые поля строятся на `onClientCharacter` |
| P6 | `dxDrawImage` поворачивается (rotX/Y/Z), есть `dxSetTransform`, `dxDrawImageSection` | transforms, 9-slice, клиппинг реализуемы платформой |
| P7 | `dxSetRenderTarget` — глобальное состояние | строго через defer-обёртку с восстановлением прежней цели |

**Whitelist MTA-API:** платформенные вызовы разрешены только в `render/backend_mta.lua`,
`input/dispatcher.lua`, `boot.lua`. Линт в CI: паттерн на вызов функции, не на упоминание в строках/комментариях.

## 3. Архитектура (LOCKED)

### 3.1 Структура

```
source/
  boot.lua        # точка сборки; единственный платформенный мост кадра и ввода
  core/           # class, signal, pool, time, log — zero-dependency
  dom/            # node, prop (схема+инвалидация), tree_ops (Z-порядок)
  layout/         # measure, flex, grid, anchors, constraints
  widget/         # base, registry, composition (slots), binding
  widgets/        # 1 файл = 1 виджет, только здесь спецификации
  render/         # canvas (command buffer), backend_mta, backend_headless
  style/          # tokens, theme, states, transitions
  input/          # dispatcher, hit_test (spatial hash), focus, gesture
  anim/           # tween, easing (единый клок из core/time)
  text/           # headless-ядро ввода: caret/selection/undo/blink
  api/            # exports.lua (import-фасад), resource isolation
  debug/          # inspector, profiler, stats overlay
```

**Правило зависимостей:** только вниз по списку; `core/` ни от кого. Нарушение — ошибка сборки.
Граф модулей генерируется из require-цепочки; циклы — ошибка сборки.

### 3.2 Контракт: свойства (dom/prop.lua) — сердце системы

```lua
local props = {
  text = {
    type        = "string",
    default     = "",
    invalidates = { DIRTY.RENDER },      -- текст можно перерисовать без раскладки
    doc         = "Отображаемый текст",
  },
  width = {
    type        = "number",
    default     = 0,
    invalidates = { DIRTY.LAYOUT, DIRTY.RENDER },
    doc         = "Ширина виджета в пикселях",
  },
}
-- Пользовательский код: побочных эффектов нет, только dirty.
node.text = "Продолжить"
```

Правила:
- Запись — только через генерируемые метаметоды (`node.<prop> = v`). Прямая запись в `_data` извне запрещена.
- Инвалидация — dirty-списки LAYOUT/RENDER (обход пассами списка, не дерева — по образцу Flutter PipelineOwner).
- Дедуп: узел в списке единожды при N записей; сброс — flushLists().
- Равное значение не инвалидирует.
- Несоответствие типа → ошибка в dev (имя виджета, свойство, ожидание, строка создания), лог в prod.
- Необъявленное свойство → ошибка схемы в dev.
- `#hex` парсится один раз при установке; в кадре — только упакованные числа.

### 3.3 Контракт: сигналы (core/signal.lua)

По контракту GoodSignal (stravant) + изоляция ошибок defold-event (Insality):

| Требование | Поведение |
|---|---|
| Connection-объекты | `connect(fn, opts) → connection`; инспектор показывает дерево подписчиков |
| Отложенная отписка | `disconnect()` внутри emit не рвёт обход |
| `opts.once` | одноразовый обработчик |
| Слабые ссылки | уничтоженный виджет отсоединяется автоматически после GC |
| Изоляция ошибок | dev: pcall + traceback, упавший подписчик не прерывает остальных; prod: без обёрток |
| Запрещённый слой | внутри фреймворка `triggerEvent` запрещён; мост один — в `boot.lua` |

```lua
-- boot.lua: единственный мост к платформенным событиям
addEventHandler("onClientClick", root, function(...)
  local dxui = getRunningInstance()  -- инстанс фреймворка
  if dxui then dxui.input.dispatch("click", ...) end
end)
```

### 3.4 Контракт: ввод

- Очередь (пул) → раздача один раз за кадр **до** пасса раскладки.
- Hit-test против геометрии **прошлого кадра** — то, что видел игрок (инвариант из постмортемов).
- Пространственный хеш: сетка 64px, `insert(rect, node)`, `query(x, y) → nodes` сверху вниз по Z;
  перестройка ленивая при структурном изменении. Ориентир: 10 000 прямоугольников / 1000 запросов ≥ 20× линейного перебора.
- Жесты: tap, long-press (500 мс), drag (порог 4px); `capturePointer()` — события до release идут владельцу.

### 3.5 Контракт: клавиатурная навигация (таблица решений — «минное поле»)

| Ситуация | Решение |
|---|---|
| Стрелки между элементами | обход по дереву раскладки, не по пикселям экрана |
| Виртуализированный список | стрелка = фокус следующей строки; список автоскроллится к фокусу |
| Контейнер прокрутки в фокус-обходе | сам контейнер пропускается; скролл следует за фокусом |
| Tab против стрелок в текстовом поле | Tab входит в редактирование, стрелка вправо — нет (иначе из поля не выйти) |
| Модальные окна и подменю | точка возволя сохраняется в стеке экранов |
| Клик вне иерархии фокуса | навигационная реконструкция от точки клика |

### 3.6 Контракт: холст и бэкенды (render/)

- Command buffer на пулах: `rect(x,y,w,h,color,opts{radius})`, `text(str,x,y,opts{font,color})`,
  `image(tex,x,y,w,h,opts{rotate,slice})`, `clip(rect)`; `clear()`, `drain()`.
- `backend_headless.lua` — исполнение в счётчики; `measureFrameTime(fn)` для CI.
- `backend_mta.lua` — единственный dxDraw: скругление шейдером с фолбэком без скругления;
  `renderToTexture(sceneFn) → texture` для RT-кэша.
- Один обработчик `onClientRender` с приоритетом из `dxui.config.lua`; viewport из `guiGetScreenSize()` (кэш).

### 3.7 Контракт: текстовое ядро (text/) — headless

Caret, выделение мышью/клавиатурой, undo-история (5 шагов), мигание курсора, clipboard —
state machine без отрисовки; отрисовка виджета читает состояние. Тестируется в CI без игры.

### 3.8 Контракт: экраны и состояние

- **Screen Stack:** `ui.Screen`: push/pop экранов с историей; переходы (fade/slide) как transition-токены; возврат восстанавливает фокус.
- **Сериализация раскладки:** `saveLayout() / loadLayout()` — позиции/размеры/тема окон в XML настроек ресурса.
- **Сценарии экранов как данные:** таблица → дерево виджетов; сервер может прислать корректировку событием.

## 4. Библиотека виджетов

### 4.1 Первый эшелон (G4)

| Группа | Виджеты | Примечание |
|---|---|---|
| Базовые | Panel, Label, Button, Checkbox, RadioButton, Image | наибольшая экономия кода |
| Ввод | Edit, Memo, Slider, Combobox | Edit — на text/ headless-ядре |
| Списки | List, GridList, TreeList | виртуализация обязательна |
| Контейнеры | Window, TabPanel, ScrollPanel, Modal, Popup, ContextMenu | единый Z-порядок; модальные ловушки |
| Обратная связь | ProgressBar, Tooltip | Tooltip — слабые ссылки, авто-скрытие |
| Специальные | Scroll, Memo-Inline, Raster-Effects | Scroll отдельно от ScrollPanel |

`Button` — эталонная схема: `text:string(required)`, `onPress:callback(required)`, `icon:texture`,
`disabled:boolean`; состояния hover/pressed из темы; transition scale 0.95 / 0.1 с.
`Window` — заголовок, drag за тайтл, resize-маркеры по краям (8), bringToFront по клику.
`Edit` — через text/-ядро; ввод на `onClientCharacter` (мост — dispatcher).

### 4.2 Второй эшелон (этапы 5–6, планом предусмотрены)

| Группа | Виджеты | Доказательство спроса |
|---|---|---|

| Продвинутый ввод | ColorPicker, DatePicker, Keybind (захват клавиши), NumericInput | ColorPicker — модуль DGS; Keybind — маст-хэв бинд-меню |
| Панели данных | Table с сортируемыми колонками, TreeList с ленивой загрузкой, Splitter | админ-панели живут на таблицах |
| Композитные | ChatBox (ввод + лог), Notification/Toast | ни один сервер не выпустился без своего чата |
| Мировые (3D) | Text3D, Billboard, WorldInterface | DGS: dx3dtext/dx3dinterface |
| Оконные | Window с resize-маркерами, DragHandle | базовое ожидание, у конкурентов частично |

### 4.3 Power-API (escape hatches — без них продвинутые уйдут писать своё)

| Возможность | Контракт |
|---|---|
| `onDraw` | пользовательский код рисует в тот же холст с тем же клиппингом/батчингом |
| Трансформации | `node.transform = { rotate, scale = {x, y}, origin }`; батчер собирает матрицы |
| 9-слайс | `image: slice = { 12, 12, 12, 12 }` — рамка не искажается при любом размере |
| Шейдеры пользователя | переменные объявляются в схеме; фолбэк при нехватке возможностей — деградация |
| Глобальный масштаб (DPI) | `tokens.scale` + множитель инстанса; применяется один раз в раскладке |
| Клиппинг | `clip = none \| rect \| rounded \| stencil(tex)` |
| Пиксельное выравнивание | `snap = true` на виджет и на инстанс |
| Drag-and-drop | единый менеджер: source → target со slots; инспектор показывает активные пары |
| Pointer capture | `widget:capturePointer()` — жесты не рвутся за пределами виджета |

## 5. Стиль и анимация

- **Токены:** palette, spacing, font, radius, scale. Тема — таблица поверх токенов; смена — батчевым обновлением.
- **Состояния:** base → hover → pressed → focused → disabled.
- **Переходы:** `{ prop = { duration, easing } }`; твины пишут через систему свойств — конвейер переиспользуется.
- **Hot-reload** тем в dev: файл перечитывается по таймеру.
- **Клоак:** единый клок из `core/time` (никаких таймеров в виджетах).
- Цвет — value-объекты с каналами r/g/b/a; парсинг строк — только при установке свойства.

```lua
-- anim: твины и таймлайны
animation.to(panel, 0.25, { x = 300, easing = "outQuad" })
Timeline { panel:fadeIn(0.2), after = animation.to(button, 0.3, { scale = 1.1 }) }
-- binding: наблюдаемый объект → свойство
binding.bind(widget, { text = observable("label.health") })
```

## 6. Производительность (реально работающие на MTA рычаги)

### 6.1 Оптимизации, заложенные в дизайн (реализовать все)

| Оптимизация | Механика | Эффект |
|---|---|---|
| Dirty-списки | пассы обходят DIRTY.LAYOUT / DIRTY.RENDER, не дерево | O(изменённого) от размера UI |
| RT-кэш статичного поддерева | растеризация в Render Target; в кадре один dxDrawImage | главный рычаг DX-оптимизации |
| Виртуализация списков | узлов O(видимых)+2; скролл подменяет данные | 10 000 строк ≈ 20 строк |
| Пулы объектов | векторы, цвета, команды холста | zero allocations steady-state |
| Коалесцирование | N записей свойств с одинаковым invalidates → один пересчёт | предсказуемая пасса |
| Заморозка скрытых поддеревьев | visibility=false — пропуск из пассов | свёрнутое окно бесплатно |
| Time-slicing | тяжёлая работа квантами ≤ 0.5 мс/кадр | нет «страшных» кадров |
| Auto-LOD эффектов | серия просадок → ступенчатое отключение: тени → размытие → скругления | деградация вместо фриза |
| Кэш строк-текстур | статичный текст → текстура; инвалидация по ключу токенов | смена темы не рвет весь кэш |
| Цвет value-объекты | упакованные числа в кадре | ноль парсинга строк в горячем пути |

### 6.2 Бюджеты (проверяются в CI, падение сборки при нарушении)

| Сценарий | Бюджет |
|---|---|
| 1000 статичных виджетов | ≤ 2 мс/кадр |
| Список 10 000 строк (виртуализованный) | ≤ 2 мс/кадр |
| 1 событие ввода + 50 виджетов | ≤ 0.2 мс |
| Смена темы, 300 виджетов | ≤ 5 мс (разовая) |
| Память на инстанс | ≤ 50 КБ после 10 минут простоя |
| Аллокации в установившемся кадре | 0 |

Методика: медиана 120 кадров после прогрева, `getTickCount`; пограничные выбросы (загрузка, шейдеры) не портят метрику.

## 8. Инструментарий

`dxui.py` (Python 3, stdlib only, ноль зависимостей):

| Команда | Назначение |
|---|---|
| `build` | генерирует meta.xml из порядка зависимостей boot.lua |
| `validate` | линт зависимостей (MTA-вызовы вне whitelist), полнота doc, структура данных плана |
| `test` | запуск тестов (headless); платформенные — по чек-листу в игре |
| `wiki` | генерация Markdown-документации из полей doc схемы |
| `new-widget <Name>` | каркас файла виджета со всеми обязательными полями схемы |

**Инспектор** (F8): дерево, видимость, фокус, подписки, живые текстуры; диагностика «почему не видно»
(visibility=false / нулевой размер / перекрыто) в один клик.
**Профилировщик:** per-widget стоимость, причины dirty (кто вызвал), `dxui:stats` overlay.
**Ошибка на языке задачи:** каждая ошибка несёт имя виджета, свойство, ожидание, строку создания — не голый трасс.
**Ко-существование:** приоритет отрисовки настраивается; инспектор предупреждает о конфликте с соседними DX-ресурсами.

## 9. Программа принятия (поставляется вместе с фреймворком)

### 9.1 Quickstart — первая страница WIKI

```lua
-- resources/my-ui/meta.xml: <include resource="dxui" />
-- Экспорт возвращает КОД (строку), исполняется один раз.
-- Прямые ссылки: WIKI предупреждает, что exports в горячем пути «убивают производительность».
local ui = loadstring(exports.dxui:import(2))()

ui.Window {
  children = {
    ui.Button { text = "Продолжить", onPress = startGame },
  },
}
```

### 9.2 Демо-ресурс (5 сценариев, каждый — отдельный файл)

| Сценарий | Что демонстрирует |
|---|---|
| Логин-панель | фокус, ввод, ограничения, темы |
| Инвентарь с поиском | виртуализация, gridlist, привязка данных, список + фильтр |
| HUD (здоровье, деньги) | anchors, кэш строк-текстур, производительность вживую |
| Банк с модальными окнами | Z-порядок, модальные ловушки, валидация формы |
| Галерея тем | тёмная/светлая/кастомная, токены, hot-reload |

Правило: каждый рецепт поваренной книги — исполняемый файл, не текст. Ни одной страницы документации без работающего кода рядом.

### 9.3 Миграция с DGS (таблица соответствия — в WIKI)

| DGS | DXUI v2 | Примечание |
|---|---|---|
| `dgsCreateButton(...)` | `ui.Button { ... }` | позиционные аргументы → именованные свойства схемы |
| `dgsSetProperty(btn, "text", ...)` | `btn.text = ...` | строковый setter → типизированное свойство |
| `onDgsMouseClick` | `widget.events.click:connect(fn)` | события платформы → сигналы |
| `dgsStyleSetProperty` | тема через токены | строки → токены с проверкой в dev |
| OOP-класс DGS | полный OOP v2 без штрафа | в DGS OOP медленнее POP (по их же WIKI); в v2 — один путь |
| `dgs-dxgridlist` | GridList с виртуализацией | 10 000 строк без деградации |

### 9.4 Дистрибуция

- Установка в два шага: скопировать ресурс + `<include resource="dxui" />`; ноль build-шагов.
- Фиксация версии: `import(2)`; внутренние слои скрыты; changelog из полей doc.
- Тема-паки и пользовательские виджеты — как отдельные ресурсы сообщества (по образцу стиль-паков DGS).

## 10. Полномочия и красные линии

**Решаешь ты без согласования:** внутренняя структура файлов внутри слоя; выбор алгоритмов в пределах бюджетов; форматы бенчмарков; тестовый дизайн; любые рефакторинги, сохраняющие контракты этапа.

**Red lines (нарушение = возврат):**
1. MTA-вызовы вне whitelist (раздел 2).
2. `triggerEvent` внутри фреймворка.
3. Аллокации в установившемся кадре (zero-alloc steady-state).
4. Строковые ключи/конкаты в горячем пути кадра.
5. Breaking-change фасада `import(2)` после G7.
6. Новые внешние зависимости (библиотека самодостаточна).
7. Расширение скоупа этапа без фиксации exit criteria.

**Опасные зоны — учесть в коде:**
- nil-дыры в children (только insert/remove-парность — `ipairs` священен);
- глобальное состояние `dxSetRenderTarget` — только defer-обёрткой;
- колесо мыши приходит без keyup (`mouse_wheel_up/down`);
- память Lua меряется `collectgarbage("count")`; пул — собственным счётчиком;
- события и порядок внутри кадра — не полагаться без явной синхронизации пассов;
- упавший обработчик в dev не должен рвать кадр (pcall в dispatcher), в prod — без обёрток.

## 11. Определение готовности (Definition of Done)

Проект завершён, когда:

1. Все G0–G7 закрыты по exit criteria, теги проставлены.
2. `grep dxDraw source/` → только `backend_mta.lua`; `grep "exports\." source/` → только объявления в `api/`.
3. Внешний ресурс собирает интерфейс через `import(2)`: логин, список с поиском, HUD, модальные диалоги, смена тем.
4. CI: validate + test + бюджеты зелёные; WIKI генерируется.
5. Двухнедельная эксплуатация демо — ни одной утечки (профайлер: живых объектов после cleanup = 0).

Риски, которые держим под контролем (двигаться этапами, не параллельно): сложность текстового рендеринга,
расползание области (каждый этап — поставка), регрессии фасада (контрактные тесты с G4).
